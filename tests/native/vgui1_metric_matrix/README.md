VM1-only metric diagnosis on the exact transient GDI-selected Arial stream.
No production candidate, dependency, filter or provider selection changes.

The actual GDI owner/constructor/bodies and current candidate library come from
the frozen matched-program control. The diagnostic extracts its exact integer
metric conversion rather than introducing a second conversion policy. Each FT
configuration owns a fresh library/face over the same in-memory stream, uses the
same cell-height-to-ppem rule, and checks the actual interpreter version. Missing
interpreter support is reported ordinarily. No font/table bytes are saved.

Finite cases: interpreter40 LCD/normal/mono; mono with COMPUTE_METRICS to isolate
the source-documented device-width path; interpreter35 LCD/normal/mono and normal
with COMPUTE_METRICS if supported; scaled unhinted metrics. Unscaled design-unit
facts plus exact scale numerators/denominators accompany the unhinted result.
The matrix records FT metrics before conversion, CBox/exact outline BBox,
advances/deltas, the unchanged converted ABC result, and GDI glyph/black-box/
origin/advance controls. It does not render or tune coverage/pixel tolerances.

Only regular Arial20/400/width0/angle0/ANSI1252 is selected. No font registration,
inventory, GUI, input, global smoothing change or hardware rendering occurs.
Getter-only smoothing/device observations and selected program/API identities
are retained. Fixed ascending byte order, no RNG. Start x64 Release/Debug and
preserve every unsupported result and mismatch; success is measurement completion,
not a new backend or a general metric-policy qualification.
