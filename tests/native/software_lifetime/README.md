# Whole-software retirement prerequisites

The production gate owns complete public-call admission, an exact executable-owned
image anchor, and a versioned terminal callback. Its resource adapter consumes the
current reviewed staged Game/Host/Listen/UI shutdown. It does not replace those
owners or infer lifetime from clipboard frame counts. These tests never start an
actual Steam session, game, window, or shared application.

The extraction runners compile the current owning method bodies with controlled
external leaves and record their source/body hashes. The remote-access test uses
the actual packet buffer and linked-list queue. The bootstrap test also imports
the actual GameUI thread-identity and retirement fence bodies. The controller test
compiles the complete browser controller/process channel and injects one failed
external process wait before the real retry/reap. The gate runner compiles the
production gate and executable ImageOwner; its resource leaf is controlled. The
clipboard candidate lane additionally links the unchanged real clipboard helper,
rejects an outstanding paste frame, then retires and physically unloads/reopens
three times. This is not full swds runtime acceptance.

Run each Python runner serially, with its output directory as the first argument.
`run_controller_completion.py` also requires the exact source-built SDL image as
its second argument. `metadata_policy.py` checks selected owning metadata and
fail-closed negatives; an optional saved before-selection JSON verifies retained
Win32 effective metadata. Run the actual dedicated host suite separately.

`../dedicated_host/actual_runtime` prepares the actual-source ModuleSet/Session
consumer for explicitly admitted isolated no-init checks and controller-only complete dedicated runs. `--module-only`
checks three independent dedicated module cold opens and physical unmaps.
`--client-no-run` checks three admitted software/font client root opens and closes
without entering `IEngineAPI::Run`. Its normal argument path runs three full real
DedicatedSession lifecycles. Actual full software-client UI/worker/provider
closure and physical unmap still require the controller's live cohort run.

The SDK owner tests import the actual provider singleton and complete session,
pump, registration and terminal functions. They distinguish active client/server
sessions from callback closure, inject partial initialization and close failures,
and verify retry plus late unregister/atexit no-effects. The checked-close test
uses the actual Provider class and a binding-only image; it invokes no SDK service.

Run all focused Debug/Release cases with CTest `-j1`. Actual component or module
probe execution requires explicit runtime admission and is never registered as an
automatic CTest service/session test. A three-cycle no-init result proves only that
exact image tuple; it does not qualify initialized engine/UI/browser/provider work.
