# Production shared SDL_GPU renderer implementation plan — v2

> **For agentic workers:** Root executes this plan with `superpowers:subagent-driven-development`: one source implementer per task, explicit source/compile leases, independent review and retained red/green evidence. Root alone runs VM1 and real desktop/device qualification. Follow the task brief rather than dispatching nested agents.

**Goal:** Render the actual CS and HL world/models/UI/media/display paths with qualified SDL_GPU D3D12 and Metal parity while retaining the OpenGL reference.

**Architecture:** Keep engine traversal and callback ABI, route owned calls into a shared semantic recorder, seal ordered owned segments of logical frames, and execute them on a persistent SDL_GPU device. Synchronous legacy read/Finish barriers execute prefixes without ending the logical frame. Private offline fixtures remain independent. Select the production GPU backend only after full functional and lifecycle qualification.

**Tech stack:** Existing C/C++, generated CMake/MSBuild manifests, pinned source-built SDL3.4.20, pinned FXC DXBC and Metal offline chains, existing Python verification helpers.

**Spec:** `docs/superpowers/specs/2026-11-11-production-sdl-gpu-renderer.md`; call ownership: historical `build/production-sdl-gpu-renderer-design-v2/source-call-inventory.json`; unresolved evidence and risks: `build/production-sdl-gpu-renderer-design-v2/risks.md`.

## Review focus

1. A browser/video texture changes or is deleted while two frames are in flight: earlier submitted pixels stay immutable and memory is released only after its fence. Tests in T1/T5/T8.
2. A GL display list or client callback contains a deferred upload/draw plus a later clear: ordering and ownership survive caller/module teardown. Tests in T1/T2/T4/T7.
3. Minimize/focus/fullscreen/Retina size changes produce NULL or changed drawable targets: no invalid submit, stale resolution or cursor/input regression. Tests in T3/T9.
4. Optional shader-on, mip/palette/low-precision/detail/wireframe state is encountered outside the first fixture profile: it is either actually implemented and compared, or the pending segment is refused and the logical frame/session is poisoned; already submitted prefixes remain recorded effects. Tests in T4/T5/T6.
5. Shader bundle/target creation/claim/allocation/submit fails midway, or a read/Finish occurs before End: acquired resources unwind, selection is explicit and no incomplete renderer appears successful; synchronous output is complete before return and subsequent draws continue without replay. Tests in T1/T2/T3/T9/T10/T11.

## Shared verification conventions

Paths below are repository-relative, and intended edits occur only in the controller-released isolated worktree. `N` abbreviates `GoldSrc-SDK/engine/render/native/` in explanatory text, never in file lists. Record negative-control output before changing semantics, then positive output for exactly the changed case. Use existing frozen or independently captured GL pixels/state, not expected values regenerated by the candidate implementation.

For each task: write the named failing test, run the narrow case and retain the expected failure, implement, run the same case plus directly affected existing tests, review diff/policies and commit only that task. **Interfaces, in `cse::render`:**
- Add `bool Recorder::AtFrameBoundary() const` returning true iff no open primitive and no list compilation; add `Status Recorder::TakeFrameDraws(std::vector<DrawPacket>& output)`. The latter succeeds only at boundary, swaps the full frame draw vector into an initially empty output, resets `frameVertices_`, and preserves textures/lists/state. On nonempty output/invalid boundary it returns `InvalidOperation` without changing either object. Existing `ClearDraws` and fixtures retain behavior.
- `enum class FrameEventKind { Draw, Clear, Readback };`
- `struct ClearEvent { std::uint32_t mask; std::array<float,4> color; double depth; std::uint32_t stencil; std::array<int,4> scissor; bool scissorEnabled; std::array<bool,4> colorWrite; bool depthWrite; std::uint32_t stencilWriteMask; };` Define private mask constants `kClearColor=1`, `kClearDepth=2`, `kClearStencil=4`; these are private bits, not copied GL enum values. Clear carries explicit masks/state so later backends do not guess GL clear semantics.
- `enum class ReadbackStage { SceneColor, PresentedColor }; struct ReadbackEvent { std::uint64_t requestId; ReadbackStage stage; std::array<int,4> rectangle; };` Coordinates in this CPU envelope are GL bottom-left pixel coordinates; later delivery conversion is explicit. ID zero is invalid; IDs must increase strictly for the recorder lifetime across frames/seals/abort. No callback/raw output pointer is stored. Duplicate/decreasing IDs are `InvalidValue`; consume the watermark only after successful event append. Exhaustion never wraps and requires a fresh session/recorder epoch.
- `struct FrameEvent { FrameEventKind kind; std::size_t drawIndex; ClearEvent clear; ReadbackEvent readback; };` Only the selected payload is interpreted.
- `struct FrameInfo { std::uint64_t serial; std::uint64_t displayEpoch; std::uint32_t width; std::uint32_t height; };`
- `struct FrameSnapshot { FrameInfo info; std::vector<FrameEvent> events; std::vector<DrawPacket> draws; };` Moveable owned value; no GL/SDL/native handle or client pointer.
- `struct FrameLimits { CaptureLimits capture; std::size_t events = kMaximumDrawPackets * 2; };` Reuse existing geometry/texture limits; event limit is bounded separately because clears/readbacks are not draws.
- `class FrameRecorder`: explicit constructor `FrameRecorder(FrameLimits limits = {})`; methods `Status BeginFrame(const FrameInfo&)`, `Status Submit(const Command&)`, `Status Clear(const ClearEvent&)`, `Status Readback(const ReadbackEvent&)`, `Status Seal(FrameSnapshot&)`, `void Abort()`, `const LegacyState& State() const`, `const TextureStore& Textures() const`; plus `Status BeginList(std::uint32_t,bool)`, `Status EndList()`, `Status DeleteList(std::uint32_t)` and `Status GenerateTextures(std::size_t,std::vector<std::uint32_t>&)` forwarding to its persistent Recorder with the same frame/error gating. No external mutable access to Recorder.
- `BeginFrame`: positive dimensions ≤ `kTextureDimension`, nonzero serial/displayEpoch, no active frame, recorder at boundary; reject otherwise unchanged. The initial renderer-frame stage permits setup commands inside a frame; out-of-frame semantic setup routing is T2's explicit initialization frame, not silent recording.
- Successful `Submit` appends a Draw event for each newly generated recorder draw, including multiple draws replayed by a list. A failed command or exhausted event limit poisons the current frame; `Seal` returns the first failure and does not alter its output. Success transfers ordered events and draws, closes frame and retains semantic state/resources for the next frame. Output must initially have empty vectors. Successful empty frames are allowed; backends decide presentation.
- `Clear` validates mask subset/nonzero, finite color/depth, depth in [0,1], nonnegative scissor extent; `Readback` validates the strictly increasing nonzero ID, exact enum membership (`SceneColor` or `PresentedColor` in T1), nonnegative x/y, strictly positive width/height, and containment using checked arithmetic. Zero-size extents are `InvalidValue`, matching the named test. A later T3 enum extension is validated explicitly, never by treating any integer as a stage. Both require active frame and boundary; neither may occur inside a list or primitive. No GPU readback occurs.
- `Abort` discards frame draws/events and error state; it must also abandon an unfinished primitive/list compilation without deleting previously completed lists/textures/state. Add `void Recorder::AbortPendingFrame()` for precisely that cleanup; retain charges for completed lists, release pending-list/upload/vertex charges and reset frame counters. Previously submitted state/texture mutations and the accepted request-ID watermark persist. This explicit method avoids using a copy of the whole recorder for rollback. Abort itself must not allocate.

**Deterministic allocation seam:** `capture_allocation.h` defines the private `enum class CaptureAllocationSite { EventGrowthAfterDraw, PendingListStorage, ListUploadCopy, TextureImageStorage, TextureObjectVersion, DrawSnapshotCopy, RecorderConstruction };`. Under fixture-only `CSE_CAPTURE_FAULT_INJECTION=1`, `void BeforeCaptureAllocation(CaptureAllocationSite)` invokes a thread-local borrowed test hook immediately before the corresponding actual allocating growth/copy/constructor operation. Production builds compile each checkpoint to a no-op and expose no hook/allocator control through client APIs. The hook type is `void (*)(CaptureAllocationSite)`; private fixture-only `CaptureAllocationHook& ActiveCaptureAllocationHook()` exposes the inline function's thread-local static to the scoped test helper; no new runtime library or process-global operator-new override. `frame_tests.cpp` owns a scoped fail-on-Nth-hit hook throwing `std::bad_alloc`; restoration is RAII and hook lifetime cannot enter a snapshot. Instrument `Recorder`/`TextureStore` only at the listed ownership allocations, not every engine allocation. Event-growth failure is injected after Recorder has appended a draw but before growing the ordered event vector, demonstrating safe sticky poisoning of this partial CPU mutation. `RecorderConstruction` is checked before initial owned store/shared-storage allocation; constructor failure propagates `bad_alloc` to the caller because constructors cannot return Status. T3's session owner catches it before creating/claiming any device/window, leaves its `unique_ptr<FrameRecorder>` empty and returns `LimitExceeded` with a diagnostic. Do not broaden exception policy beyond the planned private sources.
