# Production shared SDL_GPU renderer design

Status: reviewed implementation specification, 2026-11-11. Independent v2 architecture review accepted I1 synchronous barriers and T1 allocation/validation corrections. Root authorizes task-by-task implementation under the existing migration scope; no production GPU selection or runtime parity is implied.

## Outcome and constraints

Implement the actual Counter-Strike and Half-Life render path through one engine-owned command/state contract and a persistent SDL_GPU executor, using D3D12 on Windows x64 first and Metal on macOS ARM64 second, in Debug and Release. Keep Windows Win32 OpenGL as the comparison reference and preserve the presently functioning production OpenGL paths, including macOS. Selection stays opt-in until every applicable feature and actual-game gate passes. A colored triangle, CPU tests, or a 19-image build cannot satisfy this outcome.

Use pinned SDL 3.4.20 and existing offline FXC/Metal tooling; add no dependency, runtime shader compiler, GL emulation framework or platform renderer fork. Keep all 19 runtime outputs and per-game relative locations. Preserve source-specific FP, exception, RTTI, CRT and diagnostics policy. Retain existing assets and client/server ABI/network/save formats. Windows ARM64/Linux remain conditional migration work, not new hardware qualification projects in this design. Voice/auth/real browser functionality and campaign/save gates retain their independent ownership.

## Approaches considered and chosen

1. **Engine facade plus owned ordered frame stream and persistent SDL_GPU executor — chosen.** Keep existing CPU scene traversal, transforms, lighting, culling, resource preparation and public callback ABIs. Route the finite owned rendering API into the existing state/texture recorder, extend missing semantics, then execute admitted ordered segments of logical frames, with explicit synchronous read/Finish barriers and final presentation. This maximizes reuse and lets each real feature be compared without a second scene implementation.
2. **A new high-level world/model/UI renderer.** Could yield cleaner long-term batching, but duplicates ordering, palettes, CPU precision, UI behavior and ABI edges before equivalence is known. Reject for this parity-first migration; optimization can replace internal representations later with the same evidence.
3. **A generic GL interception/emulation layer, or embedding `RenderGpuOffscreen` in each draw.** Interception misses independent imports/context/present/shader semantics without broad platform hooking; generic GL is unnecessary scope. Per-draw offscreen allocation/wait/readback cannot be the production renderer. Reject both.

The chosen facade is private engine code with explicit wrappers for the inventoried owned calls, not an exported OpenGL implementation. Retain a direct reference GL dispatch path with unchanged GL operation ordering. Capture shadow mode is opt-in: forward to GL and record simultaneously, reporting unsupported recording without changing reference output. GPU mode uses the recorder only; it never silently forwards unsupported work to GL.

## Ordered logical frame, synchronous barriers and admission

One `RenderSession` owns state, texture/list namespace, selected backend and resource lifetime for the main game window. Main-thread callbacks submit synchronously; they cannot retain encoders or GPU handles. A logical frame can contain **multiple immutable admitted segments** before its final explicit swap/end. Each segment owns ordered draws, clears, target selections/resolves and readback events. State, resource namespaces, target contents and logical-frame counters persist across segment boundaries. No callback is replayed to reconstruct a segment.

This corrects v1's complete-frame-only submission promise. `gl_rmisc.cpp:403-438` selects front draw/read buffers, renders six envmap views with repeated `GL_BeginRendering`, immediately reads/writes each image and ends once. `gl_rmisc.cpp:469-485` finishes before and after 128 views, before end. `gl_vidnt.cpp:1064-1068,1105-1109` and `gl_screen.cpp:459-461` consume pixel memory immediately after `qglReadPixels`. Deferring those calls until final seal is invalid. T1 remains a CPU envelope; T2/T3 add the explicit segment/session bridge below before these callers can use GPU mode.

### Exact barrier and target contract

1. **Command capture.** Each draw/clear snapshots its actual draw target; each read snapshots its actual read target and pack state at the call. Logical `Front` and `Back` are separate engine-owned default color images, never aliases of “latest scene.” They share the default depth/stencil attachment as the legacy default framebuffer does. Explicit FBO draw/read bindings are independent and select their own attachments; an FBO remains distinct from default Front/Back. `DrawBuffer` never changes `ReadBuffer`. Invalid selector/binding combinations retain the reference error behavior and cannot silently select a convenient target.
2. **Synchronous read.** `ReadPixelsSync` seals only the pending prefix through that read, preflights/admit-checks that segment, executes it into owned targets with load/store continuation, schedules the requested resolve/copy at the read's exact position, submits and waits its fence, then produces owned bytes. The facade applies checked GL format/type/pack conversion and fills the caller's borrowed destination **before returning**. Draw B issued after the return cannot appear in the read of preceding draw A. No swap is implied by the read. A failure leaves the destination unchanged and terminates the legacy call through the engine error path; a void GL-compatible wrapper must not return normally so the caller can consume uninitialized data.
3. **Synchronous Finish.** `FinishSync` submits any pending admitted prefix, then waits for all session work ordered before the call, including previously submitted frames/segments. It works when the current prefix is empty or no logical frame is open. It does not read pixels or end/reset the logical frame. Subsequent draws continue with unchanged matrices, textures, viewport, targets and depth/stencil contents. The source's explicit low-latency finish after swap is still honored. This is an intentional barrier cost, not a per-draw production fence.
4. **Begin/end and envmap continuation.** `BeginLogicalFrame` is called once by the facade when the first rendering operation requires an active scope, including front drawing after Finish when no `GL_BeginRendering` preceded it. An idle Finish itself does not need to open a frame. Repeated source `GL_BeginRendering` is `BeginView`: it executes the source's viewport/target/clear commands and does not reset the frame, request IDs or attachment contents beyond those explicit clears. Thus six envmap faces have six immediate read results, each independently consumable by its existing writer, before one final `GL_EndRendering`. Target read identity follows actual binding state; if the existing scaled-FBO path reads old default Front while drawing an FBO, preserve and expose that reference behavior instead of silently substituting the FBO. Qualify both FBO and default routes against GL.
5. **Presentation boundaries.** Segment execution/resolve/readback itself never acquires the swapchain. Explicit end/swap first admits and executes the final pending segment, then acquires/composes/submits to the swapchain and performs the logical default color swap only after successful presentation submission. A NULL acquire closes the CPU logical scope without exchanging Front/Back, retaining owned target contents; a submission failure follows the poisoned-session policy. Front becomes the submitted Back content; the former Front storage can become Back, whose post-swap contents are not assumed GL-defined. Future owned reads of such contents must be checked against the source oracle, not declared equivalent by allocation choice. Default depth/stencil and explicit FBO contents are not swapped or cleared implicitly. This display-epoch/target mapping is separate from SDL's internal swapchain images.
6. **Legacy front drawing visibility.** Front-buffer drawing is not reinterpreted as Back drawing. At a synchronous barrier, if earlier commands dirtied **default Front**, an explicit internal `PublishFront` operation composes that Front to the swapchain without exchanging logical Front/Back. This is a named presentation boundary, not an implicit logical-frame end or a swap on every read: read-only Front, Back-only writes/reads and FBO-only changes do not publish. If pending commands dirty Front while the requested read selects Back, publish the dirty Front independently of that read selection. `PublishFront` follows prefix admission, execution and readback capture; it may acquire only after those resources are prepared. It uses the same final composition path as explicit swap. A NULL acquire while minimized skips visible publication but keeps Front content and returns valid readback/completion. The barrier returns only after its own publication fence signals if publication was submitted; readback bytes are copied to the caller only after the full barrier succeeds. Keep Front dirty across a skipped NULL acquisition until a later publication or logical swap supersedes it. Completion means GPU work/fence completion, not display scanout. Intermediate unsynchronized GL_FRONT scanout/tearing has no exact promise here; its visible behavior remains an explicit qualification limit, not hidden full parity. If required front-buffer observations cannot be matched with these explicit publications, the relevant mode remains unqualified.
7. **Continuation and budgets.** `SealSegment` transfers only pending owned events/draws and starts a new empty prefix while retaining cumulative logical-frame budgets, semantic state, target identities and readback-ID watermark. A segment's GPU resources retire by its own fence and monotonically increasing submission serial, not just logical-frame serial. Render-pass continuation uses load/store; resolving for a read cannot discard the multisample/depth content needed by following draws. A segment seam alone never clears a target or rewinds list/palette changes.
8. **Failure after a prefix ran.** Before any segment submits, unsupported/error cases reject that segment without GPU side effects. After a prior segment executed or a read/Front publication returned, those effects cannot be rolled back. Record `ExecutionProgress::PrefixSubmitted` or `PresentationSubmitted`, poison the logical frame, refuse further draws/readback success/final swap, discard only unsubmitted work, drain owned submitted work and end the experimental session through the diagnostic error path. Previously returned screenshots/Front publications remain historical effects; do not claim whole-frame atomic rejection, undo them, switch to GL mid-frame or replay callbacks. Startup feature admission still prevents known unsupported game/configuration profiles from being selected.

Readback request IDs are nonzero, strictly increasing for a `FrameRecorder`/`RenderSession` lifetime and not reusable across frames, segments, seal, abort or collection. An ID is consumed only when its event is successfully appended; duplicate/decreasing IDs fail `InvalidValue`, poison the current frame and leave the last accepted watermark intact. Exhaustion requires a new session epoch, never wrapping to zero. T1 rejects zero width/height, negative coordinates, overflow/out-of-bounds rectangles and out-of-range `ReadbackStage`; T3 adds a separately validated `SelectedReadBuffer` stage for legacy synchronous calls. `SceneColor`/`PresentedColor` remain explicit capture intents and never override a legacy selector.

Startup selects OpenGL unless explicitly requested. GPU startup requires compatible offline shaders, feature manifest for the intended game/configuration, ABI cohort, correct SDL driver and target support. Shadow capture keeps forwarding original GL and reports capture failures without altering reference output. GPU capture never silently forwards an unsupported operation to GL. Normal frames without synchronous barriers still submit once at end; initialization and external startup/video frames use the same rules. Each admitted submission boundary is validated before it executes; later unknown commands cannot retroactively invalidate submitted work.

## State, topology and shader equivalence

- Preserve GL matrix multiplication order, float/double conversion points and depth-range behavior. Lower GL clip depth [-w,w] to SDL_GPU [0,w] once, with viewport orientation/front-face adjustment once. Projective texture coordinates divide after perspective-correct interpolation; keep q and texture-matrix semantics rather than stripping the fourth component.
- Qualify triangles, strips, fans, quads, quad strips, polygons, lines, line loops and debug polygon line/point modes. Preserve winding/degenerates and original provoking vertex. ## GPU lifetime, window ownership and presentation

Create one persistent SDL_GPU device with driver explicitly `direct3d12` or `metal` and only the matching offline shader format. Use existing source-built SDL. Window creation on the owning main thread chooses GL flags/context only for GL; GPU windows do not create a GL context. The existing `Game` window owner continues to own window/input events, while `RenderSession` claims/releases the GPU window. Keep cursor/text-input/focus/fullscreen behavior in the existing owner.

Pinned `SDL_gpu.h:4125-4365` requires claim/acquire on the window-creation thread, documents NULL swapchain textures for unavailable/minimized windows, forbids cancel after acquiring a swapchain texture, and forbids sampling/downloading that texture. Therefore render into engine-owned SDR scene color/depth targets, resolve MSAA into an owned color texture, and compose into the swapchain as the final operation. Screenshot/readback uses owned color at a defined stage, never the write-only swapchain. Complete segment resource/pipeline allocation and admission before segment execution, and complete presentation preflight before swapchain acquisition at explicit swap or the separately defined `PublishFront` boundary. Once acquired, submit a valid command buffer even if an error requires dropping to a diagnostic final composition; record the session failure and submitted progress, and do not reuse it as a successful game frame. A pre-acquire admission failure never invokes this post-acquire recovery rule.

`FrameSlot`/segment submission records own transient vertex/index/uniform/transfer storage and resource references until the corresponding submission fence signals; multiple segments of one logical frame have distinct submission serials. Default `kFramesInFlight=2` (within pinned SDL's supported range) bounds latency; backpressure waits only when reusing an occupied slot, explicit synchronous screenshot/finish, or shutdown. No per-draw fence, readback or pipeline creation; only explicit source readback/Finish and lifecycle/backpressure barriers wait. Keep persistent pipelines by complete raster/program/attachment/sample/layout key; samplers by complete state; textures by immutable content generation. Texture-cache retention, in-flight bytes and upload/geometry bytes each have explicit byte budgets and diagnostics. Initial budgets reuse CPU capture limits where applicable; aggregate GPU budget is 512 MiB, with configuration admitted only if scene/MSAA targets plus two frame slots fit. Evict only completed, unreferenced cache entries; a budget error refuses work rather than overwriting live storage. Larger measured scenes require an explicit reviewed limit change.

Use SDL copy passes before dependent render passes. Metal upload rows stay tight because the pinned implementation's padded-row problem already has a frozen negative control; D3D12 uses its required transfer layout. Preserve source images, dimensions and channel formats, and validate multiplication overflow before allocation. Mip generation stays source CPU behavior, not an unqualified SDL convenience path.

Shutdown order: stop new producer callbacks → finish/abort open CPU frame → stop browser/video uploads → submit or cancel unacquired work correctly → wait outstanding fences → release retained frame/cache/pipeline/shader/target resources → release claimed window → destroy GPU device → destroy window → unload modules. No GPU callback or deleter may point into an unloaded client/provider.
